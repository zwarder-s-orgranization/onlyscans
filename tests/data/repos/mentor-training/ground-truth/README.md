# Как читать эталон находок

Эталон описывает заранее известные уязвимости и безопасные контрольные примеры. Пути считаются от корня проверяемого проекта. Для выгрузки результатов анализатора используйте отдельную [спецификацию](../docs/submission-format.md).

| Поле верхнего уровня | Значение |
| --- | --- |
| `dataset` | Короткое имя набора, которому относится эталон. |
| `formatVersion` | Версия структуры эталона. Сейчас `1`. |
| `findings` | Список умышленно добавленных уязвимостей. |
| `controls` | Список безопасных примеров, которые анализатор не должен отмечать как уязвимости. |

| Поле записи | Значение |
| --- | --- |
| `id` | Уникальный идентификатор записи в эталоне. |
| `category` | `SECRET` — встроенные секреты, `SAST` — ошибки кода и конфигурации, `SCA` — известные уязвимости зависимостей. |
| `class` | Код типа уязвимости. Для SECRET и SAST копируйте это значение в поле `class` отчёта. Для SCA используются координаты и `advisoryIds`. |
| `classAliases` | Справочный список альтернативных обозначений, например CWE. При заполнении отчёта используйте код из `class`. |
| `path`, `line`, `endLine` | Основной файл и диапазон строк включительно. Нумерация с 1. Для SCA `path` — файл объявления зависимости. |
| `alternateLocations` | Другие участки той же находки, каждый с `path`, `line`, `endLine`. Пустой массив означает, что дополнительных мест нет. Для SCA строки и дополнительные места объясняют, где объявлена версия, а при сверке используется основной `path`. |
| `difficulty` | Сложность обнаружения: `EASY`, `MEDIUM` или `HARD`. |
| `severity` | Серьёзность последствий. Может отличаться от сложности обнаружения. |
| `description` | Что именно уязвимо и где проявляется проблема. |
| `difficultyRationale` | Какие особенности примера определяют его сложность. |
| `expectedDetection` | Какой признак или цепочку данных должен распознать анализатор. |
| `remediation` | Рекомендуемое исправление. |
| `confirmation` | Итог проверки: `confirmed` — подтверждено, `pending` — требуется подтверждение. |
| `verification` | Способ подтверждения находки: `passed-behavior-test` — по поведению приложения, `resolved-advisory-crosscheck` — по сверке разрешённой версии с advisory, `source-review` — по исходному коду, `advisory-only` — по advisory. |
| `scanners` | Сводка фактических запусков по имени отчёта. Структура записи описана ниже. |
| `expectedFinding`, `reason` | Только у контрольных примеров. `expectedFinding: false` означает, что срабатывания быть не должно. `reason` объясняет, почему. |

| Дополнительное поле SCA | Значение |
| --- | --- |
| `group`, `artifact`, `version` | Maven-группа, имя артефакта и фактически разрешённая Gradle версия. |
| `advisoryIds` | Идентификаторы описания уязвимости (например, CVE или GHSA). У контроля это advisory, которое не применяется к указанной версии. |
| `sources` | Ссылки на источники описания уязвимости. |
| `cvss` | Числовая оценка серьёзности по CVSS. |
| `affected` | Уязвимый диапазон и указанная в advisory исправленная версия. Квадратные скобки включают границу диапазона, круглые исключают. |

| Поле внутри `scanners` | Значение |
| --- | --- |
| `status` | `detected` — найдено совпадение, `missed` — совпадения нет, `partial` — Semgrep отметил нужный участок, но совпадение само по себе не подтверждает весь контекст, `failed` — запуск не дал пригодного отчёта, `not_run` — запуск не зафиксирован. |
| `report` | Имя исходного JSON-отчёта, если указано. |
| `identifiers` | Идентификаторы совпавших правил сканера или advisory. Пустой массив означает отсутствие совпадений. |
