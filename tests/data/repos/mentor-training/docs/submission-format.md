# Формат отчёта анализаторов

Выгружайте результаты SECRET, SAST и SCA в один JSON-файл в кодировке UTF-8. В корне файла должен быть один объект с массивом `findings`. Каждая запись массива описывает одну находку. Если находок нет, выгрузите `{"findings": []}`, а в читаемом отчёте сообщите, что находок нет.

Используйте точные имена ключей, включая регистр. Строки заключайте в двойные кавычки. Не добавляйте комментарии и запятые после последних элементов. Обязательные строки должны содержать хотя бы один непробельный символ. Необязательные поля, для которых нет данных, опускайте.

## Общие поля

| Ключ | Тип JSON | Обязательный | Значение |
| --- | --- | --- | --- |
| `findings` | Массив объектов | Да, в корне файла | Все находки. Допустим пустой массив `[]`. |
| `category` | Строка | Да, в каждой находке | `SECRET` для встроенных секретов, `SAST` для уязвимостей кода и конфигурации, `SCA` для известных уязвимостей зависимостей. Это три допустимых значения. Для экспорта используйте верхний регистр. |
| `path` | Строка | Да, в каждой находке | Путь к файлу относительно корня проекта, например `src/main/resources/application.yml`. Для SCA это файл объявления зависимости, обычно `build.gradle.kts`. |
| `severity` | Строка | Нет | Серьёзность последствий. Рекомендуемый словарь включает `LOW` (низкая), `MEDIUM` (средняя), `HIGH` (высокая), `CRITICAL` (критическая). |
| `description` | Строка | Нет | Что обнаружено, где это проявляется и к каким последствиям может привести. Для SECRET опишите назначение секрета и место его хранения, не раскрывая значение. |
| `remediation` | Строка | Нет | Конкретный способ исправления, например вынести секрет в переменную окружения или обновить зависимость. |

В `path` используйте `/` между частями пути. Разделитель Windows тоже допустим. В тексте JSON обратную косую черту экранируют, например `"src\\main\\resources\\application.yml"`. Абсолютные пути, буквы дисков, двоеточие и компонент `..` недопустимы. Указывайте имя файла с тем же регистром, что в проекте.

## Поля SECRET и SAST

Добавляйте эти поля к общим полям находки.

| Ключ | Тип JSON | Обязательный | Значение |
| --- | --- | --- | --- |
| `class` | Строка | Да | Код типа уязвимости. Для типов из таблицы используйте приведённое значение с тем же регистром и дефисами. Для других типов можно указать свой код. |
| `line` | Целое число JSON | Да | Первая строка находки в файле. Счёт начинается с 1. Передавайте число, например `13`. |
| `endLine` | Целое число JSON | Нет | Последняя строка находки. Если поля нет, используется значение `line`. |

Обе границы включены. Длина диапазона от 1 до 15 строк, поэтому `line ≤ endLine ≤ line + 14`. Для одной строки достаточно `line`. При наличии `endLine` укажите целое число. Строки вроде `"13"`, дробные числа, логические значения и `null` для номеров строк недопустимы.

### Классы учебных находок

| Категория | Код `class` | Значение |
| --- | --- | --- |
| SECRET | `password` | Встроенный пароль |
| SECRET | `api-key` | Встроенный ключ API |
| SECRET | `configuration-token` | Токен в конфигурации |
| SECRET | `secret-fallback` | Встроенный секрет, используемый по умолчанию |
| SECRET | `recoverable-token` | Токен, восстанавливаемый из исходников |
| SAST | `sql-injection` | SQL-инъекция |
| SAST | `tls-verification` | Ослабленная проверка TLS |
| SAST | `credentialed-cors` | Излишне широкий CORS с учётными данными |
| SAST | `route-authorization` | Ошибка проверки доступа к маршруту |
| SAST | `object-authorization` | Ошибка проверки доступа к объекту |

В читаемом отчёте опишите суть проблемы своими словами. В JSON этот текст можно добавить в необязательное поле `description`. Например, для `class: "sql-injection"` подойдёт «Параметр запроса подставляется в SQL без параметризации».

## Поля SCA

Добавляйте эти поля к общим полям находки. Поля `class`, `line` и `endLine` для SCA не требуются.

| Ключ | Тип JSON | Обязательный | Значение |
| --- | --- | --- | --- |
| `group` | Строка | Да | Maven-группа, например `org.apache.commons`. |
| `artifact` | Строка | Да | Имя артефакта, например `commons-text`. |
| `version` | Строка | Да | Точная версия зависимости, например `"1.9"` или `"20230227"`. Найдите значение переменной или свойства Gradle, если версия задана через них. Если версия есть в `gradle.lockfile`, используйте запись из него. |
| `advisoryId` | Строка | Да | Один идентификатор уязвимости из справочника. Используйте `id` записи, например `GHSA-599f-7c49-w659`, или её CVE из `aliases`, например `CVE-2022-42889`. |

Копируйте Maven-координаты точно, включая регистр и запись версии. Если одной версии соответствуют несколько разных уязвимостей, создайте отдельную находку для каждой. Если CVE и GHSA указывают на одну и ту же уязвимость, выберите один идентификатор. В отчёте используется ключ `advisoryId` с одним значением. Массив `advisoryIds` относится к эталону.

## Пример отчёта

```json
{
  "findings": [
    {
      "category": "SECRET",
      "path": "src/main/kotlin/lab/repairdesk/integration/QuoteRequest.kt",
      "class": "api-key",
      "line": 7,
      "severity": "MEDIUM",
      "description": "Встроенный API-ключ используется в заголовке X-Api-Key",
      "remediation": "Передавать ключ через настройки окружения"
    },
    {
      "category": "SAST",
      "path": "src/main/kotlin/lab/repairdesk/repair/RepairLookupController.kt",
      "class": "sql-injection",
      "line": 13,
      "endLine": 14
    },
    {
      "category": "SCA",
      "path": "build.gradle.kts",
      "group": "org.apache.commons",
      "artifact": "commons-text",
      "version": "1.9",
      "advisoryId": "CVE-2022-42889"
    }
  ]
}
```
